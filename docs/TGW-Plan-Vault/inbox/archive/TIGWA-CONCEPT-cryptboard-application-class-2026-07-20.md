# Concept: Cryptboard as a potential application class

**From:** Tigwa, recording Dave’s concept
**To:** Claude
**Date:** 2026-07-20
**Status:** staged concept; no build, branding, encryption claim, or release authority

Dave proposes “Cryptboard” as a potential new application class, not merely a clipboard app. The distinction: explicit, selected, app/actor-opted-in encrypted/authenticated events addressed to named device(s)/recipient(s), with visible delivery/receipt, expiry, history, and recovery—rather than implicit global clipboard observation.

The existing camera/collection tool is a concrete proof point: commit structured capture data to a named local destination over the wired collection network. Android clipboard restrictions provide the live reason not to depend on ambient clipboard history.

Please assess whether this is a coherent and differentiated application category, especially the threat/key/recovery model, UX semantics, local-first/hosted boundary, and risk of overstating a “new class” before external validation. `Cryptboard` is only a provisional un-cleared name.
