## Sub-finding #1298 — 7 direct atomic_write_json() calls in api.py silently skipped archive_root

`items.py`'s own helpers (`update_item`, `strip_fields`, `create_item`) always pass
`archive_root` to `atomic_write_json()`, which archives an existing item JSON to a zip
under `archive_root` before overwriting (invariant E5). Several direct callers in
`api.py` imported `atomic_write_json` straight from `tgw.items` and called it without
`archive_root`, silently skipping the archive-before-overwrite protection on an
existing item's JSON. Fixed all 7 sites to pass `archive_root=cfg.get('archive_root')`:

- `cmd_catalog_verify` (catalog-verify --mark-verified) — api.py line ~1783
- `cmd_hint` — api.py line ~1902
- `cmd_resolve_legacy` (legacy-listing resolve) — api.py line ~2302
- `cmd_price_freeship` (freeship-apply) — api.py line ~3119
- `cmd_set_template` — api.py line ~3762
- `quality --save` CLI dispatch branch — api.py line ~4168
- `lookup --save` CLI dispatch branch — api.py line ~4205

## Sub-finding #1299 — migrate-unblock field-removal write skipped archive_root

`migrate-unblock`'s destructive field removal (`doc.pop("sku_migrate_blocked", None)`,
`doc.pop("sku_migrate_skip", None)`) wrote back via `atomic_write_json()` with no
`archive_root`. Fixed — api.py line ~4538, same pattern as #1298.

## Sub-finding #1300 — migrate-restore missing dest-exists check

`migrate-restore` only checked `dest.parent.exists()` before writing the restored
snapshot to `dest`, never checking whether `dest` (the live item JSON) already
existed — a restore could silently clobber a live item created/renamed into that
SKU path after the archive snapshot was taken. No pre-existing `--force`-style flag
existed on this subcommand. Added:

- A new `--force` flag scoped to the `migrate-restore` subparser only (not global) —
  api.py `_build_parser()`, ~line 830-834.
- A refuse-by-default check: if `dest.exists()` and not `args.force`, print
  `"Destination already has a live item — refusing to overwrite: <path>. Use --force
  to override."` and return 1 — api.py ~line 4586.
- `archive_root=cfg.get('archive_root')` added to this call site's `atomic_write_json`
  too (via the `_awj` alias), for consistency with the rest of the fix — api.py
  ~line 4603.
