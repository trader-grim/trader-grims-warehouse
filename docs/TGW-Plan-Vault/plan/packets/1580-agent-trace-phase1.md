  `_AI_USAGE_DDL` vs `schema.sql`'s own `ai_usage CREATE TABLE`). Do not repeat this
  silently — the in-code DDL in `state_machine.py` is the one actually applied at

## Spec
1. **New Postgres table `agent_runs`**, added as in-code self-apply DDL in
   `state_machine.py` (mirror `_ensure_ai_usage_table()`'s pattern: a
   `_AGENT_RUNS_DDL` constant, a `_ensure_agent_runs_table()` function guarded by a
   module-level `_agent_runs_table_ready` bool, called before the first insert/update).
   Columns:
   - `run_id TEXT PRIMARY KEY` (a uuid4 hex string, generated by the CLI/caller, not
     `SERIAL` — callers need to know the ID before the row exists, to reference it in
     `parent_run_id` for nested dispatches)
   - `parent_run_id TEXT REFERENCES agent_runs(run_id)` (nullable)
   - `agent_type TEXT NOT NULL` (free-form string — e.g. `claude-main`, `claude-subagent`,
     `tgw-coder`, `nix-flake-maintainer`, `aider` — no enum CHECK constraint; new agent
     types will appear over time and a hardcoded CHECK would need a migration every time,
     which defeats the point)
   - `todo_id INTEGER` (nullable, no FK — `todo_items` may not have every id populated
     at insert time in edge cases; nullable is correct, not a shortcut)
   - `pp_ref TEXT` (nullable)
   - `host TEXT` (nullable — e.g. `tgw-prod`, `a1131`)
   - `git_branch TEXT` (nullable)
   - `started_at TIMESTAMPTZ NOT NULL DEFAULT NOW()`
   - `ended_at TIMESTAMPTZ` (nullable — null while running)
   - `status TEXT NOT NULL DEFAULT 'running'` with `CHECK (status IN ('running',
     'completed', 'failed', 'killed', 'escalated'))`
   - `summary TEXT` (nullable — one-line, set at end)
   - `transcript_path TEXT` (nullable — path under `/opt/TGW/var/agent-traces/`)
   Add a matching `CREATE TABLE IF NOT EXISTS agent_runs (...)` block to `schema.sql`
   too, as bootstrap-doc parity — clearly commented that `state_machine.py`'s in-code
   DDL is the one actually applied, this is documentation only (same caveat that should
   really exist on `ai_usage` today but doesn't — don't silently repeat that gap, name
   it in a comment on both copies).
2. **Two functions in `state_machine.py`** (or a new small module if that file is
   already very large — your call, but keep it next to `record_ai_usage()`'s pattern
   if it fits): `start_agent_run(agent_type, *, parent_run_id=None, todo_id=None,
   pp_ref=None, host=None, git_branch=None) -> str` (returns a new `run_id`, inserts the
   row) and `end_agent_run(run_id, *, status, summary=None, transcript_path=None) ->
   None` (updates `ended_at=NOW()`, `status`, `summary`, `transcript_path`). Both call
   `_ensure_agent_runs_table()` first, same as `record_ai_usage()` does for
   `_ensure_ai_usage_table()`.
3. **New `tgw trace` CLI subcommand family** (wherever the existing `tgw todo`/`tgw
   plan` subcommands are wired into the CLI entrypoint — follow that exact pattern):
   - `tgw trace start --agent-type TYPE [--parent-run-id ID] [--todo ID] [--pp REF]
     [--host HOST] [--git-branch BRANCH]` — calls `start_agent_run()`, prints the new
     `run_id` to stdout (and only the run_id — this needs to be trivially captured by
     a calling shell script, e.g. `RUN_ID=$(tgw trace start --agent-type aider)`).
   - `tgw trace end RUN_ID --status {completed,failed,killed,escalated} [--summary
     TEXT] [--transcript PATH]` — calls `end_agent_run()`.
   - `--host`/`--git-branch` should default-detect if not passed (hostname via
     `socket.gethostname()` or equivalent already used elsewhere in this codebase —
     check for an existing helper before adding a new one; git branch via `git rev-
     parse --abbrev-ref HEAD` in the caller's cwd, best-effort, `None` on failure —
     never raise on a git-detection failure, this is metadata, not the point of the
     command).
4. **Raw transcript archival helper**: a function (e.g. in `logging.py` or the new
   trace module) `archive_transcript(run_id, source_path) -> str` that copies
   `source_path` into `/opt/TGW/var/agent-traces/{today's date}/{run_id}.jsonl`
   (directory created if missing, `tgw`-owned per existing conventions), using the
   same atomic-write discipline used elsewhere for ItemData (invariant E5 — write to a
   temp file in the same target dir, then `os.replace()`; do not partially-write then
   crash leaving a corrupt file). Returns the final path (for `tgw trace end
   --transcript` to record). This is a standalone helper — Phase 1 does NOT need to
   wire it into any live hook (that's Phase 4, todo #1583); Phase 1 just needs the
   function to exist and be tested, callable manually or by a future caller.
5. Unit tests for all of the above: `start_agent_run`/`end_agent_run` round-trip
   (insert then read back, verify columns), the `status` CHECK constraint rejects an
   invalid value, `parent_run_id` FK behavior, the CLI subcommands (via subprocess or
   direct function call, whichever this codebase's existing CLI tests already do —
   check `tests/test_todo.py` or equivalent for the pattern), and
   `archive_transcript()`'s atomic-write behavior (including: source file doesn't
   exist → clear error, not a silent no-op; target dir doesn't exist yet → created).

## Dataset
This IS new durable data (Prime Directive 1 applies directly): agent run metadata +
raw transcripts become a new permanent asset class, parallel to ItemData. `agent_runs`
rows are the "derived index"; the archived transcript files under
`/opt/TGW/var/agent-traces/` are the "raw" layer per the Data Charter split — raw is
permanent, never pruned by this packet (no TTL/retention logic — Dave confirmed
permanent retention as the default for this initiative 2026-07-20).
