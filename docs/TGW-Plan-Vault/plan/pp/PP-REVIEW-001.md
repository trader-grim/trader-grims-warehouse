## PP-REVIEW-001 — Pipeline Review Workflow

**Opened:** 2026-06-20 (session 35)
**Status:** Phase 1 PENDING
**Driver:** Any pipeline stage can hit a permanent-but-fixable failure (eBay policy violation,
bad data, AI misidentification). Today those items land in dead-letter or stage-specific blocked
fields with no unified review surface, no operator self-service, and no path back to the pipeline
without developer intervention. PP-MIGRATE-001 built this for migration only; PP-REVIEW-001
generalises it across every pipeline stage.

### Core principle

An item in a blocked/failed state is not lost — it needs human judgment to resolve. The system
must make that judgment as easy as possible: show what failed, why, what to do about it, let the
operator fix it, and put it back in the pipeline without code changes.

### Data model

Each worker that hits a permanent failure writes a `review_block` to the item JSON:

```json
"review_block": {
  "stage":       "ebay_publish",          // which worker blocked it
  "reason_code": "POLICY_VIOLATION",      // machine-readable code
  "error":       "eBay errorId 25019 …",  // raw error (truncated)
  "suggestion":  "Remove 'Hearing Aid' from title — eBay flags medical device claims …",
  "flagged_at":  "2026-06-20T14:20:21Z",
  "retested_at": null,                    // last auto-retest timestamp
  "ready":       false                    // operator sets true to re-queue
}
```

`suggestion` is generated by a Haiku 4.5 call: error text + item title/description → one-paragraph
actionable fix. Generated once at block time; can be regenerated by operator request.

Stage-specific block fields (`sku_migrate_blocked`, etc.) remain as-is for backwards compat.
`review_block` is the canonical cross-stage field the review surface reads from.

### Review surface

The review UI (and CLI) shows:
- All items with `review_block.ready = false`, grouped by `stage` and `reason_code`
- Per item: sku, title, stage, reason, suggestion, time blocked
- Drill-down → item editor with `review_block` displayed as a sidebar panel
- "Mark Ready" button → sets `review_block.ready = true`, re-queues to originating stage
- "Regenerate suggestion" → fires a new Haiku 4.5 call

### Re-queue path

When `ready = true`:
- `ebay_publish` stage → enqueue `ebay_publish` job
- `ebay_draft` stage → enqueue `ebay_draft` job
- `ebay_sku_migrate` stage → clear `sku_migrate_skip`, enqueue migration batch
- etc. — each stage registers its re-queue handler

### Auto-retest

A `review_check` worker (or cron on existing workers) periodically retests items where:
- `review_block.ready = false`
- `review_block.retested_at` is null or > 24h ago
- The error was transient (e.g., eBay rate limit, temporary policy state)

On success: clears `review_block`, continues pipeline. On failure: updates `retested_at`.

### Phases

- **Phase 1 ✅ COMPLETE (2026-06-20)** — Standard review_block shape + general review surface
  - `review_block` field: stage, reason_code, error, suggestion, flagged_at, retested_at, ready
  - `_reason_code()` in ebay_sku_migrate maps error text to POLICY_VIOLATION / DATA_CONSTRAINT / etc.
  - ebay_sku_migrate permanent failures now write `review_block` alongside `sku_migrate_blocked`
  - Existing blocked item backfilled with `review_block` (tgw20170507112030106)
  - `GET /api/review?stage=&reason_code=` — catalog scan via json_extract; returns items + grouped
  - `tgw review [--stage] [--reason]` CLI — grouped table with SKU, flagged time, title, error
  - Catalog rebuild: `DELETE + INSERT` (was `INSERT OR REPLACE`) — stale rows now purged on rebuild

- **Phase 2 — Re-queue from review**
  - `POST /api/items/{sku}/action review_ready` — sets ready, re-queues to originating stage
  - `tgw review-ready <sku>` CLI
  - Stage re-queue registry (maps stage name → enqueue function)

- **Phase 3 — AI suggestion (Haiku 4.5)**
  - Haiku 4.5 call at block time: error + item title/description → suggestion
  - `POST /api/items/{sku}/action review_suggest` — regenerate on demand
  - `tgw review-suggest <sku>` CLI

- **Phase 4 — Auto-retest**
  - `review_check` worker: scans items with `review_block.ready = false`, retests transient errors
  - Configurable retest interval and transient-error pattern list

### Reason codes (initial set)

| Code | Description |
|------|-------------|
| `POLICY_VIOLATION` | eBay errorId 25019 — content policy |
| `DATA_CONSTRAINT` | eBay errorId 25002/25004 — invalid field value |
| `NO_PRICE` | Item has no price set |
| `AI_LOW_CONFIDENCE` | ai_identify confidence below threshold |
| `MANUAL` | Operator-flagged for review |
